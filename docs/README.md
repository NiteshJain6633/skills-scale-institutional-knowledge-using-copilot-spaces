# OctoAcme Project Management Docs

This folder contains OctoAcme's project management guidance, from initial project approval through delivery, release, and continuous improvement.

## Project management processes at a glance

OctoAcme manages work through an iterative lifecycle: initiate and validate the need, plan scope and milestones, execute and track delivery, release and verify changes, then capture lessons in retrospectives. Projects start with a one-pager that defines the problem, objective, success metrics, stakeholders, timeline, risks, and resource needs, followed by a go/no-go decision before planning begins.

Delivery is organized around clear ownership and visible work. The Project Manager coordinates plans, risks, dependencies, schedules, and stakeholder communication; the Product Manager defines outcomes and prioritizes the backlog; Developers implement, test, review, and document changes; and QA validates quality and acceptance criteria. Work moves through a project board from backlog to ready, in progress, review, QA, and done. Regular standups, delivery syncs, reviews, demos, stakeholder updates, and risk reviews keep teams aligned and expose blockers early.

Quality is built into planning and execution. Teams define acceptance criteria and a Definition of Done, use small pull requests with linked issues, run unit, integration, end-to-end, and manual QA tests as appropriate, and enforce CI checks, security scanning, and reviews before merging. Releases require passing checks, completed acceptance criteria, prepared smoke tests, release notes, rollback plans, and post-deployment verification. Retrospectives identify improvements and create owned, dated actions that feed back into the backlog, supporting continuous learning and repeatable delivery.
